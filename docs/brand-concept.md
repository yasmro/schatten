# Brand Concept

> 本書は `apps/docs` のブランドページ（#449 Phase 3）の **SSOT**。
> サイトはこれを描画するだけで、ブランドの一次情報を持たない
> （#449 論点 (3) の「新しい view は既存 SSOT の消費者として設計する」原則）。
>
> **§1 はコードから検証できる事実のみ**（数値は v1.0.0 時点）。
> §2–3 が確定したコンセプト、§4 が唯一の未決事項。
>
> 置き場所について: 美学は「実装者の correctness 違反」を表現しないため
> `.claude/rules/` の採用基準（#102 で spacing の美観ルールを wontfix にした
> 基準）を満たさない。よって `docs/` に置く。

## 1. 事実 — コードに実装されている語彙

以下はすべて `src/core/tokens/primitives.css` と
`src/themes/seasonal/themes.css` から検証できる。数値は v1.0.0 時点。

### 1.1 色名は和の語彙で構成されている

| primitive | 語源 | 代表値（-500） | 役割 |
|---|---|---|---|
| `vermillion` | 朱 | `oklch(0.62 0.22 30)` | ブランドの主色 |
| `red` | 紅（危険色） | `oklch(0.64 0.18 22)` | error / destructive |
| `sumi` | 墨 | `oklch(0.58 0.01 250)` | 前景・文字 |
| `alabaster` | 和紙（白練） | `oklch(0.58 0.01 70)` | 面・背景 |
| `indigo` | 藍 | `oklch(0.55 0.16 265)` | 補助のブランド色 |
| `paper-*` | 紙 | `#fafafa` / `#f5f3f0` / `#f0ede8` | 素の紙面 3 段 |
| `ink-*` | 墨色 | `sumi-*` へのエイリアス | 濃度別の墨 |

`ink-*` は `sumi-*` の、反転時は `alabaster-*` のエイリアスとして定義される
（`--ink-black: var(--sumi-900)` / `--ink-black-inverted: var(--alabaster-200)`）。
**墨と紙が反転して入れ替わる**構造が、トークン定義そのものに書かれている。

### 1.2 墨は寒色、紙は暖色 — 彩度は同じ

`sumi-500` と `alabaster-500` は**明度も彩度も同一**（L 0.58 / C 0.01）で、
**色相だけが 250 と 70 で正反対**。どちらもほぼ無彩色に見えるが、
墨は青みへ、紙は黄みへ倒れている。偶然では起こりえない設計。

この「明度で差をつけず、色相の寒暖で差をつける」原則は、
機能面でも再利用されている: `disabled` は `gray-*`（寒色）、
`readOnly` は `alabaster-*`（暖色）を使い、同じ明度帯で意味を分ける
（[state-token-guideline](../.claude/rules/state-token-guideline.md#cool-vs-warm--why-two-hue-families)）。
**美学の語彙が、そのまま機能の識別子として働いている。**

#### 墨と和紙は、全 11 段が鏡像である

§1.2 の関係は `-500` だけの話ではない。**梯子のすべての段で明度・彩度が一致し、
色相だけが 250 と 70 で分かれている**:

| 段 | 50 | 100 | 200 | 300 | 400 | 500 | 600 | 700 | 800 | 900 | 950 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| L | .98 | .96 | .91 | .83 | .71 | .58 | .48 | .37 | .27 | .18 | .12 |
| C | .005 | .008 | .01 | .01 | .01 | .01 | .01 | .01 | .01 | .01 | .008 |

墨（h250）と和紙（h70）はこの表を**共有**する。つまり両者は
同じ階調構造を持つ一対であり、寒暖だけが違う。

### 1.3 朱と紅は分岐済み

`vermillion`（朱）は色相 30・彩度 0.22、`red`（紅）は色相 22・彩度 0.18。
**ブランド朱の方が暖かく鮮やか、危険の紅は寒く抑えめ**。全シェードで一貫している。

もともと両者は同値のコピーで、「ブランド色と危険色を独立に調整可能にする」
ための governance seam として分離された（#238）。実際に色味を分けるかは
デザイン判断として #239 に切り出され、**#239 は 2026-05-29 にクローズ、
分岐が実装された**。

### 1.4 季節は色相だけが動き、明度の梯子は共有される

8 つの Special テーマは `--color-theme-*` のランプのみを差し替える。
500 段はすべて **L 64%**、700 段はすべて **L 46%** で固定され、
動くのは色相と彩度だけ:

| | 春・早 | 春・晩 | 夏・早 | 夏・盛 | 秋・早 | 秋・晩 | 冬・早 | 冬・深 |
|---|---|---|---|---|---|---|---|---|
| 色相 | 12 | 138 | 162 | 45 | 230 | 70 | 250 | 255 |

結果として、どの季節を選んでもコントラスト構造が壊れない。
**季節は「色」を運ぶが「読みやすさ」は動かさない**、という設計が
数値として保証されている（[theme-architecture](../.claude/rules/theme-architecture.md#solid-rides-the-theme-ramp)）。

### 1.5 季節の区切りは八節（四立 + 二至二分）

季節の期間境界は
[`src/themes/seasonal/index.ts`](../src/themes/seasonal/index.ts) に定義され、
その日付は**古典的な八節**と一致する:

| 開始 | 2/4 | 3/21 | 5/6 | 6/21 | 8/7 | 9/23 | 11/7 | 12/22 |
|---|---|---|---|---|---|---|---|---|
| 節気 | 立春 | 春分 | 立夏 | 夏至 | 立秋 | 秋分 | 立冬 | 冬至 |

四立（立春・立夏・立秋・立冬）と二至二分（春分・秋分・夏至・冬至）による
八分割で、二十四節気の親にあたる区切り。**8 という数は恣意的ではなく、
暦の構造そのもの**である。

### 1.6 書体と、その尺度

**フェイス** — sans / serif の両ロールとも、欧文と和文を明示的に対にして
ひとつのスタックを組む（`--font-sans` / `--font-serif`）:

| 役割 | 欧文 | 和文 |
|---|---|---|
| sans（UI・本文） | Hanken Grotesk | LINE Seed JP |
| serif（見出し・長文） | EB Garamond | Noto Serif JP |

**尺度** — サイズは 8 段、行送りは 6 段。いずれも Tailwind 互換の
公開トークンで、`rem` 基準（[api-stability の四層モデル](../.claude/rules/api-stability.md#css-variable-naming--the-four-layer-model)
の第 2 層 = 慣習を共有する層）:

| token | 値 | | token | 値 |
|---|---|---|---|---|
| `--text-xs` | 0.75rem | | `--leading-none` | 1 |
| `--text-sm` | 0.875rem | | `--leading-tight` | 1.25 |
| `--text-base` | 1rem | | `--leading-snug` | 1.375 |
| `--text-lg` | 1.125rem | | `--leading-normal` | 1.5 |
| `--text-xl` | 1.25rem | | `--leading-relaxed` | 1.625 |
| `--text-2xl` | 1.5rem | | `--leading-loose` | 2 |
| `--text-3xl` | 1.875rem | | | |
| `--text-4xl` | 2.25rem | | | |

なお **typography のロール（body / label / heading）は CSS 変数ではなく
`.st-text--*` のクラス規則に束ねられている**。サイズ・行送り・ウェイトの
3 プロパティを 1 つの `var()` では表現できないため
（[css-api の多プロパティ束](../.claude/rules/css-api.md#multi-property-bundles-bind-on-the-class-not-on-a-token)）。

### 1.7 名前

**Schatten** はドイツ語で「影」。

## 2. コンセプト

### 2.1 テーゼ

> **陰影とは、光の不在ではなく、紙と墨のあいだに生まれる階調である。**
> Schatten は「影」を名に持ちながら、それを黒ではなく
> **墨（寒い無彩）と和紙（暖かい無彩）**の対比として定義する。
> **朱と藍**はその静かな面に許された二つの色——儀礼の熱と日常の冷——であり、
> **八節**の巡りは色を替えても、紙と墨の階調（すなわち読みやすさ）には
> 決して触れない。

### 2.2 二つの言語を同時に話す

Schatten の**構造**は西洋の工学語彙でできている（shadcn / Radix / OKLCH /
BEM / CVA）。**表層**は和の美学語彙でできている（朱・墨・和紙・藍・八節）。
どちらも他方の装飾ではなく、対等に組み合わさっている。

この二重性は名前と色名だけの話ではなく、**組版のレベルで実装されている**
（§1.6）。sans も serif も、欧文フェイスと和文フェイスを明示的にペアにして
1 つのスタックを構成している。**バイリンガルであることが、系の既定状態**。

## 3. 各論

### 3.1 朱は聖であって、危険ではない

日本文化における朱は「聖」と「危険」の両義を持つが、Schatten は
**危険の意味を朱から剥がした**。#238 で `red` を分離して seam を作り、
#239 で分岐を決定、#327 で `vermillion` を**伝統的な真朱**（hue 30、
鳥居・印章・漆の朱）へ動かし、危険の紅は hue 22 に据え置いた（§1.3）。

つまり**色相の分岐が、そのまま意味の分岐**になっている。
朱はブランドの熱であり、警告色ではない。

### 3.2 藍は朱の対であり、余り物ではない

この系には**寒暖の対が二重にある**:

| | 暖 | 寒 |
|---|---|---|
| 無彩（C ≈ 0.01） | 和紙 70 | 墨 250 |
| 有彩 | 朱 30（C 0.22） | 藍 265（C 0.16） |

藍（265）は墨（250）のすぐ隣にあり、いわば**「彩度を持った墨」**。
日本の色彩感覚でも藍染・紺は日常・実用の側、朱は儀礼・聖の側で、
これは古典的な対をなす。

**藍の consumer が薄いのは埋めるべき空白であって、藍が予約席である
証拠ではない。** ただし `info` は blue に固定する規約があるため
（[state-token-guideline](../.claude/rules/state-token-guideline.md#info-independence-from-the-theme-scale)）、
藍に情報色を担わせてはならない。第二のブランド色として扱う。

### 3.3 八節は暦の主張であって、機構のショーケースではない

季節の区切りは古典的な八節と一致する（§1.5）。8 という数は
テーマ機構の都合ではなく、暦の構造から来ている。したがって
**季節はブランドの中核**であり、How it's built 側の話題ではない。

同時に、八節は**色だけを運び、明度の梯子には触れない**（§1.4）。
巡る季節と、動かない可読性。この二層構造そのものが主張である。

### 3.4 影は elevation ではない

「影を名乗るのに影が少ない」——この問いへの答えは、
**Schatten の陰影は `box-shadow` ではなく、墨と和紙の階調である**。
名前は elevation を約束していない。

なお `--shadow-card` を「自然な consumer が現れるまで使わない」と
した define-only 運用（[decision log](decisions/2026-06-shadow-card-define-only.md)）は
**トークン運用の規律であって、ブランドの表明ではない**。
名前と役割が合わない consumer にトークンを当てない、という一般則の適用例。

## 6. サイトへの反映（Phase 3）

`apps/docs` にブランドページを追加する。データソースは**本書（手書きプローズ）**、
ただし色・書体・季節の**値はすべて生成**し、drift を防ぐ
（#449 論点 (3) の SSOT → 消費者マップに行を追加する）。

| ページ要素 | 生成元 | drift gate |
|---|---|---|
| コンセプト散文 | 本書 | なし（人手） |
| 四色（朱・墨・和紙・藍） | `dist/schatten.css` | 生成につき自動追従 |
| 墨 / 和紙の鏡像ランプ（11 段 × 2） | `src/core/tokens/primitives.css` | 同上 |
| 朱 ≠ 紅 の対比 | 同上 | 同上 |
| 季節ランプ（八節） | `src/themes/seasonal/themes.css` | 同上 |
| 型の尺度（`--text-*` / `--leading-*`） | `dist/schatten.css` | 同上 |

### Storybook `Tokens/*` との線引き（二重化の回避）

Storybook 側には既に `Tokens/Color` / `Tokens/Typography` などが存在し、
#449 論点 (2) は**二重化を原則禁止**としている。両者の役割は次で分ける:

- **ブランドページ（サイト）** — *なぜ*その色と書体なのか。
  見せるのは**選ばれた少数**（四色・鏡像ランプ・八節・2 つのフェイス対）と、
  それが意味すること。読者は評価者。
- **`Tokens/*`（Storybook）** — *何が使えるのか*。全スケール・全段・全状態の
  網羅的リファレンス。読者は実装者。

同じ値が両方に現れるのは許容する（生成元が同一なので drift しない）。
禁じるのは**同じ役割のページを二つ持つこと**。したがってブランドページに
全 11 段 × 全スケールの一覧を載せてはならない ― それは `Tokens/*` の仕事。
