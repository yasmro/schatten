# Lighthouse 100 — Vanilla HTML example

A plain static HTML page that targets a **100/100/100/100** Lighthouse
score (Performance / Accessibility / Best Practices / SEO) while using
Schatten's `.st-*` class API — no React, no bundler, no JavaScript
runtime on the consumer side.

## Setup

```sh
pnpm install
pnpm build          # runs scripts/prepare-css.mjs — inlines tokens, copies component CSS
pnpm start          # serves the built page from public/ at http://localhost:4173
```

In a second terminal:

```sh
pnpm lhci           # runs @lhci/cli 3× and asserts all categories scored 100
```

The `lhci` script reads `lighthouserc.json`, starts the static server,
hits `http://localhost:4173`, and exits non-zero if any of the four
categories slipped below 100.

## What `prepare-css.mjs` does

The template at [`src/index.template.html`](src/index.template.html)
carries two placeholder comments inside `<style>` tags:

```html
<style>/* @inline:core/tokens */</style>
<style>/* @inline:themes/default */</style>
```

[`scripts/prepare-css.mjs`](scripts/prepare-css.mjs) substitutes each
placeholder with the contents of the corresponding CSS file from
`node_modules/@yasmro/schatten/dist/`. It also copies
`dist/css/button.css` + `dist/css/badge.css` into `public/css/` so the
`<link rel="preload">` tags in the template resolve to local paths.

The result is a single self-contained `public/index.html` plus two
small CSS files in `public/css/` that the preload tags can reach.

## Why this scores well

| Technique | What it addresses |
|---|---|
| **Tokens inlined as `<style>` in `<head>`** | No render-blocking `<link>` for the foundation; first paint already has the correct color scheme and typography |
| **Component CSS via `preload` + `onload` swap** | The stylesheet downloads in parallel with first paint; once it arrives, `onload="this.rel='stylesheet'"` promotes it to a render-applying stylesheet without a second round-trip |
| **`<noscript>` fallback** | If JavaScript is disabled the `<noscript>` block loads the CSS as a normal blocking stylesheet — page is still styled |
| **No runtime JavaScript** | The `.st-*` class API is plain CSS — no React mount, no hydration, no client bundle. Best Practices and SEO benefit indirectly via the small total payload |

## How it maps to Lighthouse audits

The corresponding [Performance section in the main
README](../../../README.md#performance) maps each technique to the
audit it addresses. The two most directly affected here:

- **Reduce unused CSS** — only Button + Badge selectors are loaded.
- **Eliminate render-blocking resources** — tokens are inlined and
  component CSS is preloaded; nothing on the critical path waits for
  the network.

## Pointing at the worktree's source

By default, `@yasmro/schatten` resolves to the latest npm release. To
test changes from a worktree:

```sh
# From the repo root:
pnpm build

# In this example's package.json, change "@yasmro/schatten" to "file:../../.."
# Then in this directory:
pnpm install
pnpm build
```
