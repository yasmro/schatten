# `src/__generated__/`

Files in this directory are **machine-generated** and form the input side of
Schatten's CI gates. Do not edit them by hand.

## `schatten.manifest.json`

The committed snapshot of Schatten's public CSS API — every `.st-*` class,
every `[data-*]` / `[aria-invalid]` / `[aria-busy]` styling hook, and every
CSS custom property declared in the `@layer theme { :root, :host { … } }`
registrar (`src/styles/public-tokens.css` since #317; previously compiled by
Tailwind v4 from `@theme { … }` registrations — the extraction criterion,
"declared inside `@layer theme`", is unchanged) of the compiled
`dist/schatten.css`. Custom properties declared elsewhere in the source token
files (font-weight scalars, fallback stacks, sub-step spacing values) are
implementation primitives and intentionally excluded.

Owned by `scripts/generate-manifest.mjs`. Regenerated by
`pnpm update:manifest`.

### When to regenerate

When you have intentionally changed the public CSS surface — added a new
`.st-*` class in a sweep PR, retuned which state hooks a component reacts
to, removed a CSS variable — the CI gate (`pnpm check:manifest`) will fail
until this file matches the regenerated output. Run:

```sh
pnpm build              # rebuild dist/schatten.css
pnpm update:manifest    # rewrite this file from dist
```

Then commit the change **together with** a changeset that uses the
`CSS API:` prefix to explain the surface change in the rendered CHANGELOG.

### Why this file does not include `version` / `generatedAt`

The companion `dist/schatten.manifest.json` (the version consumers download
from npm) carries `package`, `version`, and `generatedAt` for in-the-wild
introspection. This committed copy intentionally omits them — including
either field would mean every `changeset version` (which bumps
`package.json#version`) silently churns the snapshot, making the develop→main
release PR look like it changed the public surface. Keeping this file
surface-only means the only time it changes is when the surface itself
moves.

### What "drift detected" means in CI

`scripts/check-manifest-diff.mjs` regenerates the manifest from the freshly
built `dist/schatten.css` and compares against this file. A drift means
either:

- **You forgot `pnpm update:manifest`.** Run it, commit, push.
- **You did not realise the change affected the public surface.** That is
  exactly what this gate is for. Decide whether the change is intentional
  (re-run `pnpm update:manifest`, add a `CSS API:` changeset) or
  accidental (revert the offending CSS edit).

See `.claude/rules/api-stability.md` and `.claude/rules/css-api.md` for the
contract that decides what counts as a public-surface change.
